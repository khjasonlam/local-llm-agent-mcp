# 教材の動作確認手順（運営用）

勉強会の前に、教材が参加者と同じ環境で動くか、どのくらい時間がかかるかを確かめる手順です。
Mac・Windows のどちらでも使えます。新しい回の教材ができたときや、いつもと違う PC（Windows、メモリ 8GB など）で確かめたいときに使ってください。

30分〜1時間ほど、PCを置いておける時間にお願いします（ほとんどは待ち時間です）。

## 1. 事前準備ページの手順1〜4を済ませる

事前準備ページ: https://claude.ai/artifact/FJ1vs8KyhSSfeNxXNA2idG

Ollama・モデル2つ（`qwen3.5:0.8b` と、メモリに合わせて `qwen3.5:4b` か `qwen3.5:2b`）・uv が入っていれば大丈夫です。
このほかに git を使います。

## 2. ターミナルを開く

| | 開き方 |
| --- | --- |
| Mac | 「ターミナル」アプリを開く（Spotlight で「ターミナル」と入力） |
| Windows | 「PowerShell」を開く（スタートメニューで「PowerShell」と入力） |

以降のコマンドは、Mac・Windows とも同じです。

## 3. リポジトリを取ってくる

教材を置きたい場所（例: ドキュメント）で、次を実行します。参加者に配る教材に、確認用のスクリプト（`internal/tools/verify_session1.py` など、回ごとに1つ）が入った状態で取ってこられます。

```
git clone https://github.com/khjasonlam/local-llm-agent-mcp.git
cd local-llm-agent-mcp
```

2回目以降は、`local-llm-agent-mcp` フォルダで `git pull` を実行すれば最新になります。

## 4. 確認用のスクリプトを実行する

続けて、同じターミナルで次を実行します。

```
uv sync
uv run internal/tools/verify_session1.py --quick
```

| 実行のしかた | かかる時間の目安 | 使いどころ |
| --- | --- | --- |
| `--quick` を付ける | 10分前後 | ふだんの確認。比較（4.1）の候補の質問を1回ずつ試す |
| `--quick` を付けない | 20分前後 | 質問を変えたときなど。比較の候補を3回ずつ試して、ばらつきを見る |

`[時刻] 完了しました。` と出たら終わりです。途中でエラーが出て止まった場合も、そこまでの結果は残ります。

## 5. 結果を送る

`local-llm-agent-mcp` フォルダの中の `internal/verify_results/session1/` に、日時の名前のフォルダができています（第2回なら `session2/`）。そのフォルダを zip にして、Jason に送ってください。

| | zip にする方法 |
| --- | --- |
| Mac | フォルダを右クリック →「圧縮」 |
| Windows | フォルダを右クリック →「圧縮先」→「ZIP ファイル」（Windows 10 は「送る」→「圧縮（zip 形式）フォルダー」） |

あわせて、次の3つを教えてください。

- PCの機種とメモリ（Mac はチップ名も。例: M2・16GB。Windows は GPU の有無もわかる範囲で）
- OS のバージョン（例: macOS 15、Windows 11）
- 実行中に気づいたこと（画面の表示が崩れた、PCが重くなった、など）

## 確認したいこと（運営メモ）

- 教材のスクリプト（本編と「もっと試す」の両方）が、すべて終了コード 0 で終わるか（結果の `1x_*.txt` の2行目）
- 比較（4.1）が1問あたり何秒かかるか。Mac（M系・4b）では1問1分〜1分半（小さいモデル約25秒＋大きいモデル30秒〜1分）
- 3.2 の珍しい漢字の質問（`1x_3.2_answer_tokens_rare.txt`）で「（文字の一部）」が出るか。当日資料の 3.2 の観察で使っている
- 3.2 の `--temperature 0` を2回実行した結果（`1x_3.2_answer_tokens_temp0_a.txt` と `_b.txt`）が同じ答えになるか
- 2.3 で、履歴ありの2回目は「ほうじ茶」と答え、履歴なしの2回目は「ほうじ茶」と答えないか（「覚えていない」と答えるか、別の飲み物を当てずっぽうで答える）
- 日本語・罫線・棒グラフ（█）が崩れずに表示されるか。特に Windows の PowerShell（結果ファイルとは別に、画面の見え方も聞く）
- 確認用のスクリプトは回ごとに分けている。第2回・第3回の教材ができたら、`verify_session2.py` のように新しく作り、共通の処理は `verify_common.py` を使う
